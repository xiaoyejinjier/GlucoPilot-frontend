# 用户端设备添加（准备阶段）

入口：记录页“今日九时段记录”右侧的蓝色“绑定设备”，跳转全屏 `frontend/pages/device-add/device-add`。导航标题为“添加设备”，使用系统返回；直接打开页面时，底部“返回记录”也可回到记录页。

## 当前已实现

- 卡通助手空状态、开机/蓝牙提示；仅点击“搜索附近设备”后初始化BLE并发现附近设备，约12秒后自动停止。离页会停止、解除本页监听、释放本页适配器；重复启动先等待旧搜索清理。
- 发现结果按设备标识去重、按信号排列，最多展示30台。未知型号不声称是血糖仪，不自动连接、配对或读取特征。
- 扫码调用微信原生扫码，支持二维码、条码、Data Matrix；只提取SN，进入确认表单，不自动登记、不打开或请求码中的URL。当前接受纯SN、含`sn`/`serialNumber`的JSON、含这两个查询字段的HTTP(S) URL。这是准备阶段通用规则，非厂商认证码规则。
- SN暂按4–64位校验，允许字母、数字、点、横线、下划线，以字母或数字开头；保留大小写。具体厂商规则确认后再调整。
- 候选设备允许登记、去重和移除，统一显示“待适配 · 未绑定”。只存于本次登录会话内存（最多20台），重启小程序或登录会话变化会清空，不写本地持久化、服务器或数据库。
- 微信开发者工具提示到真机搜索；蓝牙未开启、权限不足、扫码取消/失败和非法设备码分别处理。系统相机导致hide/show时保留同账号待确认结果，离页/换账号的晚回调不得回写。

微信API参考：[官方类型定义（蓝牙与扫码）](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)、[蓝牙初始化](https://developers.weixin.qq.com/miniprogram/dev/api/device/bluetooth/wx.openBluetoothAdapter.html)、[搜索附近设备](https://developers.weixin.qq.com/miniprogram/dev/api/device/bluetooth/wx.startBluetoothDevicesDiscovery.html)。发布前在微信公众平台按实际功能配置小程序隐私说明和相关API声明；手机系统也需允许微信的蓝牙/附近设备权限，部分系统的搜索条件不同，需真机检查。

## 尚未实现，不可作为已绑定功能演示

当前用户尚未选定真实设备，没有品牌型号、SDK/通信协议或绑定接口。没有实现厂商校验、设备配对、云端设备归属、自动读取/解码血糖或自动写入九时段记录；不生成任何模拟读数。

后续确认设备的BLE服务/特征UUID、配对与认证、数据帧/校验、单位、时间和序号规则，再编写独立厂商适配器。必须区分扫描到、验证通过、已绑定、连接中、已连接、正在同步和同步失败，不能把扫描到当成绑定成功。读数进入界面前校验来源、单位和时间；入库前确认用户/时段/截止规则、历史与实时区分、重复读数幂等，并先更新`API-CONTRACT.md`，由接口负责人实现服务端。

## 验证与交接

本地测试：`node --test tools/tests/device-add.test.cjs tools/tests/device-discovery.test.cjs`，全部使用模拟微信API，不扫描真实设备、不写共享数据库。视觉预览只是浏览器中的WXML/WXSS等价布局，不能代替微信开发者工具或真机。

手机验收：重新编译正确的小程序目录，确认入口/返回；蓝牙关闭与权限拒绝时显示说明；开蓝牙后手动搜索，停止/超时/离页均结束；扫码取消不登记，合法码须确认；SN错误不登记、重复不增加；登录变化清空；原拍照、手动输入、提醒及曲线不变。
