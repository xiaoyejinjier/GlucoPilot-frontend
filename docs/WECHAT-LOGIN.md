# 两个微信账号真机互发

私信服务已经支持不同C端用户互发。真实微信身份需要后端把wx.login()的临时code交给微信校验，不能用code哈希、设备标识或用户自行填写的openid冒充登录。

## 服务端配置

在本机已忽略的`.env`或部署环境里填写，不要把AppSecret发到小程序、提交Git或打印到日志：

```dotenv
WECHAT_LOGIN_MODE=wechat
WECHAT_APP_ID=填写该小程序的AppID
WECHAT_APP_SECRET=填写该小程序的AppSecret
```

AppID必须与开发者工具/两台手机运行的小程序一致；AppSecret由该小程序管理员在微信公众平台开发设置中配置。测试号或没有有效AppSecret的环境不能当成真实微信登录已验收。

若刚获取的code也被提示失效，先核对服务端WECHAT_APP_ID、project.config.json的appid及开发者工具“详情”显示的AppID是否一致。修改项目AppID后关闭并重新打开项目、重新编译，再点击微信登录以获取新code；后端.env变更则需重启后端，避免继续使用旧配置。

更换AppID或换手机后，需在每台真机重新设置开发后端地址；原AppID、模拟器与另一台手机的Storage不能当成本机已有配置。保持手机与电脑在同一Wi-Fi，在该手机的真机调试Console执行`wx.setStorageSync('apiBaseUrl', 'http://<电脑WLAN地址>:8080/api/v1')`，再点击登录即可，不需要清缓存或恢复登录页的开发测试面板。只在普通模拟器Console设置不会配置手机；正式版不接受此开发覆盖。

更新并重启当前工作区后端，再编译小程序。原dev Mock账号与真实微信账号不会自动合并，不覆盖原来的记录。mode=wechat缺配置会明确拒绝登录；auto仅在完整配置时接真实微信，配置了一半不降级；没有任何凭据时只在dev/test允许保留原Mock，prod禁止Mock。

## 两台手机操作

1. 两人各自用自己的微信登录同一个小程序，并完成首次免责声明。手机必须都能访问统一配置的后端地址。
2. 各自在“我的”查看并点击复制社区号，例如u123；两人的社区号必须不同。若相同说明登录身份相同，不能通过更换昵称来解决。
3. 手机A打开“社区 → 找用户”，粘贴B的社区号，打开公开资料后点“发私信”；B在“私信”列表进入并回复。也可搜索对方昵称。
4. 聊天页和私信列表首屏每5秒更新；打开消息后显示已读，退出页面停止轮询。重复发送/断网重试复用请求标识，不重复入库。

当前手机号验证码仍是后端日志方式，没有真实短信网关；本次没有增加开发账号选择按钮，也没有把任意手机号或任意code当成已验证身份。

## 验证边界

本机已经通过运行中的HTTP接口和真实MySQL，用新建的隔离验收身份检查A找B、A→B、B→A、未读、已读、重复发送、第三人隔离；结束时清理这些临时身份、会话与消息。该检查验证私信及鉴权链路，不代替两台手机wx.login()和微信服务的实际验收。
